## Overview

**StageFlow v1.1.1** is a focused reliability, performance, and exporter usability patch on top of `v1.1.0`. It eliminates idle WebGL/CPU churn when paused, resolves 60fps/10Hz shot-boundary desync glitched frames, fixes Observer Camera snap resets across score transitions and hydration, and adds a **Custom (`s`)** dual-handle timeline scrubber to the in-browser WebCodecs MP4 exporter.

---

## What's New & Fixed in v1.1.1

### ⚡ Idle WebGL/CPU Loop Elimination, Memoized Rigs & 60fps Shot-Cut Sync Gate ([#9](https://github.com/taruma/stageflow/issues/9) / PR [#11](https://github.com/taruma/stageflow/pull/11))
- **On-Demand Canvas Rendering**: Both `DioramaCanvas` and `StageCamMonitorCanvas` now run `frameloop="demand"` while paused, waking immediately on orbits, resize transitions, preset snaps, async `<Text>` font loads, and manual seeks (`onSeekSettled` / `onTimeJump`), while short-circuiting redundant idle `computeStageFrame()` calls.
- **Rig & Mannequin Memoization**: Memoized `DirectionalMannequin`, `BlueprintFloorGrid`, and `StageCameraRigMount`, hoisted static arrays and unconditional hooks, delta-guarded DOM/GPU tether buffer updates (`StageBillboardLabel`, `StageCameraFocusRig`, `StageCameraOffsetTether`), added Three.js `.dispose()` resource cleanups, moved frame-invariant thin-lens DoF denominator math to CPU (`uOpticalScale`), and throttled MP4 export progress flushes (`~100ms`).
- **Shot & Cue Boundary Sync Gate (`stageSyncGate.ts`)**: Added `resolveGatedState()` with `useLayoutEffect` synchronization across gated rigs, mannequins, focus/offset tethers, mounts, and the WebGL2 DoF pass to hold the last rendered 60fps state across async boundary commits instead of snapping back to stale 10Hz `uiFrame` snapshots.

### ✂️ Custom Time Range (`Custom (s)`) & Dual-Handle Scrubber for MP4 Export ([#13](https://github.com/taruma/stageflow/issues/13) / PR [#14](https://github.com/taruma/stageflow/pull/14))
- **Shot-Aware Dual-Handle Scrubber**: Extended `Time Range` in `File ▾ → Export Video (.mp4)...` with `Custom (s)`, featuring a drag-only dual-handle timeline scrubber (`ExportRangeScrubber` / `ExportRangeScrubberTrack`) with shot cut dividers, hover timecode readout, and inline decimal `Start (s)` / `End (s)` inputs (`0.1s` step, preserving 3-decimal scene durations such as `45.375s` and `61.625s`).
- **Validation & Range-Tagged Output Filenames**: Pure Layer 1 validation (`validateCustomExportRange` in `src/core/exportMath.ts` + `src/core/exportScrubberMath.ts`) guards against negative, inverted, out-of-bounds, or sub-frame (`< 1 / fps`) selections, while `formatExportMp4Filename()` emits `_<start>s-<end>s_` tags (e.g., `vector_field_2_5s-6s_stage_cam_1080p_60fps.mp4`).

### 🎯 Observer Camera Snap & Clock Reset on Score Transitions ([#8](https://github.com/taruma/stageflow/issues/8) / PR [#15](https://github.com/taruma/stageflow/pull/15))
- **Deterministic `sceneResetSeq` Transition Signal**: Opening, creating, forking/duplicating, deleting (fallback), resetting, importing, or asynchronously hydrating a score (`IndexedDB`, `?score=`, `?remoteUrl=`) atomically resets `cameraMode` to `'scripted'`, pauses and seeks the clock to `t = 0`, clears stale `shotId` gate refs, flushes residual `OrbitControls` damping deltas, and snaps the Observer Camera cleanly to `frame.observerCamera.transform`.
- **Non-Disruptive Live YAML Editing**: Added `MediaClockDriver.setDuration()` in-place updates (`Html5MediaDriver`, `YouTubeMediaDriver`, `ProceduralMediaDriver`) so live YAML edits and in-place renames preserve playhead `t`, playback state, and paused free-orbit camera angles.
